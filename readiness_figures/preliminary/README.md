# Preliminary Readiness Figures

Generated by `../../plot_readiness_preliminary.py`. This directory is separate
from retained campaign data, production figures and thesis files.

Only the renderer, this README and `verify_figures.py` are versioned here.
PNG/PDF exports, logs, generated CSVs and metadata remain local ignored artifacts.
Reproduction requires a separate archive of the retained readiness analysis CSVs
and the historical mini_app reference CSV described below. The verifier reads
the local generated metadata, summaries and exports, so render them first on a
fresh checkout. Existing site-specific provenance paths document the original
installation; the source commits do not back up those datasets or temporary helpers.

Model display labels are `[TS] WaterCNN` and `[TS] Giant MLP`. `[TS]` identifies
the terrain-solver source class, distinguishing it from TBL; it does not rename
models, CSV keys or output files. This display-only revision also applies to the
current original final CPU terrain campaign figures, not historical archives.

`step_latency.png` (400 dpi) and `step_latency.pdf` compare five replicate means
of ten steady solver ML steps as arithmetic-mean columns, not individual step
measurements. Each column uses exactly five replicate means per
model/configuration. Capped whiskers show sample SD across those five means,
not confidence intervals. No individual measurement points are drawn.
WaterCNN uses ms; Giant uses s. Only the fresh
PhyDLL Default and Readiness measurements are paired. AIx uses arithmetic
replicate means from the historical production_4644312 performance dataset,
not medians. Its original dataset and Score-P settings differ. Historical AIx
is a reference, not a paired or controlled readiness comparison. Pairing is
not drawn. The summary CSV retains the mean, sample SD, replicate count and
all five replicate means in ms.

`dl_phases.png` (400 dpi) and `dl_phases.pdf` show only the validated,
exclusive, disjoint DL phase bins for the two fresh PhyDLL modes. Grouped bars
use zero-based linear axes, without broken axes or measurement points.
Whiskers show sample SD across the five replicate group sums, not confidence
intervals. WaterCNN uses ms; Giant uses s; labels give means in panel units.
Small columns are intentionally small on the shared panel scale; numeric
labels sit directly above their own column at mean plus SD with the same
six-point offset for both modes, without staggered levels. Staging
includes allocation, input unpack/staging, output staging/reorder and residual
DL overhead. Per-replicate group sums are computed before their mean and SD.
Times average 96 DL ranks and ten steady calls; they are not whole-step
makespans. No solver receive/readiness time is added to DL forward.

`watercnn_comparison.png/.pdf` and `giant_mlp_comparison.png/.pdf` each have
two horizontal panels: Whole ML-step mean latency and SD on the left (historical
AIx reference, PhyDLL Default, PhyDLL Readiness), and DL phase means and SD on
the right (the two fresh PhyDLL modes). WaterCNN uses ms in both panels; Giant
MLP uses seconds. Both panels within each comparison share y-axis limits and
ticks. They reuse the same data and rendering functions as the
separate figures. All four figures use linear axes starting at zero, decimal
labels, no measurement points, and no explanatory captions or reduction titles.
PNG files are 400 dpi; PDFs retain vector bars, text and whiskers.

`memory_peak_aggregation.csv` is a new table, preserving the original memory
means. It gives mean, maximum, sample SD and minimum in GiB across five
per-run simultaneous total process-set PSS/RSS sampled peaks. Max-of-max is
appropriate for the largest observed footprint, not a typical run or a
theoretical worst case. It does not sum independent process or role maxima.
Sampling is non-atomic and can miss peaks; sweep duration is recorded. PSS
apportions shared pages, while RSS can count them repeatedly. Neither is a
cgroup/cache/kernel memory limit measurement.

`step_latency_summary.csv`, `dl_phases_summary.csv` and `plot_metadata.json`
record numeric plot data, statistics, source paths/hashes and validation.
The phase summary records group sums for all five replicates, their count,
mean and sample SD in ms, allowing independent recomputation. Both comparison
figures use these same summary tables. Superseded phase artifacts are removed
by the renderer after replacements are written.
The source CSVs are read-only and their hashes are checked again after rendering.
The renderer rejects duplicate/missing replicate keys, non-finite measurements,
inconsistent paired/step/run means, invalid DL phase scope/count/normalization,
and invalid memory census. No statistical significance claims are made.

The metadata records the UTC generation time, command and Slurm job ID.
Provenance and statistical explanations are kept here and in metadata, not
inside the graphics. No source datasets are changed by rendering. The original
render log `render_4720566.log` is retained as historical provenance, not as
the validation record for the revised figures.
